# UserProfile DataStore 迁移测试文档

<!-- CREATED_BY_AGENT -->

## 1. 变更概述

### 1.1 修改背景

`UserProfileManager` 的缓存逻辑从 **MMKV 分字段存储** 迁移到 **DataStore + JSON 序列化整体存储**。

### 1.2 主要变更

| 项目 | 旧方案 (MMKV) | 新方案 (DataStore) |
|------|---------------|-------------------|
| 存储方式 | 分字段存储 (`setUserProfileData`) | JSON 整体序列化 (`jsonDataStore`) |
| 读取方式 | 同步读取 (`getUserProfileData`) | 异步 Flow (`profile`) |
| 存在性检查 | 同步 (`hasUserProfileData`) | 异步 Flow (`hasUserProfile`) |
| 文件位置 | MMKV 默认目录 | `user_profile.json` |

### 1.3 影响范围

以下文件使用了 `UserProfileManager`：

- `MainViewModel.kt` - 用户信息展示、登出
- `ChatViewModel.kt` - 聊天页用户信息、生图功能
- `ProfileViewModel.kt` - 个人资料页
- `ModifyProfileViewModel.kt` - 编辑个人资料
- `SettingViewModel.kt` - 设置页用户邮箱
- `RegInfoViewModel.kt` - 注册信息完善
- `UnifiedStartupManager.kt` - 启动时同步用户信息
- `UserProfileRepository.kt` - 用户外观更新
- `MainActivity.kt` - 登录流程

## 2. 已识别的潜在风险

### 2.1 高优先级风险

| 风险ID | 风险描述 | 影响 | 缓解措施 |
|--------|----------|------|----------|
| R-001 | 初始状态为空 UserProfile | UI 可能显示空白或默认值 | 检查 `id.isNotEmpty()` 后再使用 |
| R-002 | 登出时异步清理与同步状态更新竞争 | 状态不一致 | 确保清理完成后再更新状态 |
| R-003 | 旧版本升级数据丢失 | 用户需重新登录 | 实现数据迁移逻辑（如需要） |

### 2.2 中优先级风险

| 风险ID | 风险描述 | 影响 | 缓解措施 |
|--------|----------|------|----------|
| R-004 | `first()` 调用可能阻塞 | 用户操作延迟 | 添加超时机制 |
| R-005 | Main 线程调用 DataStore 写入 | UI 卡顿 | 切换到 IO 线程 |
| R-006 | Firebase 事件上报空用户信息 | 数据分析不准确 | 检查数据有效性后再上报 |
