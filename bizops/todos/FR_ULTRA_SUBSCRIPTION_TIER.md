# Ultra 订阅层级项目计划

## 目标与背景
- 在现有订阅体系基础上新增 **Ultra** 层级，提供更高价值、更清晰的差异化权益。
- 提升高价值用户转化率与 ARPU，同时保持现有订阅用户体验稳定。
- 以可配置、可灰度的方式落地，降低计费、权限与内容发布风险。

## 成功指标（可量化）
- Ultra 新增订阅转化率（从曝光到购买）达到既定目标（待定）。
- Ultra 订阅用户 30 天留存高于现有最高层级。
- 订阅状态一致性（后端/客户端/支付渠道）达到 99.9% 以上。
- 退款率与客服工单增量控制在可接受范围内（待定阈值）。

## 用户分层与价值主张（草案）
- **目标人群**：已认可 Premium 价值、使用频率高、对更接近无限制体验敏感的用户。
- **Ultra 核心主张**：在 Premium 基础上提供 **更“Unlimited”** 的服务体验与额外优惠权益。

## 权益矩阵（草案）
> 具体数值与权益需与产品/运营确认后定稿。

| 权益维度 | Free | Premium | Ultra |
| --- | --- | --- | --- |
| 模型能力 | 基础模型 | 进阶模型 | 顶级模型/优先模型 |
| 使用额度 | 基础配额 | 提升配额 | 更接近 Unlimited（含公平使用/高水位上限） |
| 速度与排队 | 普通 | 优先 | 最高优先级（更少排队） |
| 高级功能 | 限制使用 | 部分开放 | 全量开放 |
| 客服与支持 | 标准 | 优先 | 最高优先级 |
| 专属内容 | 无 | 可选 | 专属权益 + 额外优惠 |

## 范围界定

### In Scope
- 新增 Ultra SKU 与计费配置（Android/Web），**复用现有订阅逻辑与流程**。
- 订阅状态与权益控制（后端 + 客户端），与 Premium 逻辑一致的设置方式。
- 订阅升级/降级/续订/退款流程全链路支持（不新增新流程）。
- Paywall、账户页、权益说明、订阅状态展示。
- 埋点与监控（转化、留存、退款、支付失败等）。

### Out of Scope
- 新模型训练或基础能力研发（若涉及，需另立项目）。
- 大规模 UI 重构或主题系统改造。
- 与第三方线下权益绑定（除非单独审批）。

## 系统与技术方案（概览）

### 数据与权限
- 新增订阅层级枚举（例如 `SUBSCRIPTION_TIER_ULTRA`），**沿用 Premium 现有订阅逻辑**。
- 统一权益表（entitlements）与额度策略，支持远程配置与灰度；额度策略体现“更接近 Unlimited”。
- 订阅状态同步：支付渠道 → 后端 → 客户端（Android/Web）。

### 后端（app/ + alembic）
- 订阅与权益 API 扩展：
  - 获取订阅状态与权益：`GET /api/v1/subscription/status`
  - 升级/降级入口：`POST /api/v1/subscription/plan`
  - 支付回执验证与 webhook 处理
- 数据模型更新：订阅层级、有效期、渠道、回执信息。
- 审计日志：升级/降级/退款记录可追踪。

### Android（android_app/）
- Billing SKU 新增与配置（含区域定价）。
- Paywall 与权益说明组件更新。
- 订阅状态展示与权益 gating（逻辑与 Premium 一致）。
- 订阅异常处理（支付失败、订阅失效、降级）。

### Web（web_app/）
- Web paywall 与订阅管理入口。
- 支付渠道接入与回执验证流程配合。
- 订阅状态展示与权益 gating（逻辑与 Premium 一致）。

### 运营后台（evaluation/）
- 用户订阅状态查询与人工补偿入口。
- 关键指标面板（转化、退款、流失）。

## 里程碑与交付物（建议）

### Phase 0：调研与对齐（1 周）
- 订阅体系现状梳理与数据基线建立。
- Ultra 权益/定价/渠道策略初稿。
- 关键流程与风险评审。

### Phase 1：设计与方案定稿（1-2 周）
- 权益矩阵最终版 + Paywall 文案与视觉方案。
- API 与数据模型方案评审通过。
- 监控与埋点清单确定。

### Phase 2：开发实现（2-4 周）
- 后端订阅体系扩展 + webhook + 权限校验。
- Android/Web 新 SKU 与 UI 入口上线灰度。
- 运营后台查询与补偿能力。

### Phase 3：测试与灰度（1-2 周）
- 端到端订阅流程测试（购买、续订、退款、升级/降级）。
- 灰度发布与指标观测，逐步扩量。

### Phase 4：全量发布与复盘（1 周）
- 全量开放 Ultra。
- 复盘与指标评估，确定后续优化方向。

## 风险与对策
- **订阅状态不同步**：建立多源校验与每日对账；客户端提示刷新与重试。
- **价格敏感导致转化低**：灰度价格与权益组合，结合 AB 测试迭代。
- **退款率上升**：强化权益说明与试用/限时优惠策略。
- **计费渠道合规风险**：支付规则评审与法律合规确认。

## 依赖与待确认事项
- 现有订阅层级命名与定价策略。

- 客服与运营资源投入计划。

## 验收标准
- Ultra 订阅购买、续订、取消、退款流程闭环可用。
- 订阅状态与权益在 Android/Web/后端一致。
- 关键埋点上报准确且可追踪。
- 灰度期间核心指标达到预期阈值（转化/留存/退款）。
