# 聊天中增加用户时间上下文（Experimental）

## 目标
在单条消息内向模型提供“用户本地时间”上下文，帮助角色更自然地理解用户所处时间段；强调时间只用于理解用户处境，AI 不需要睡觉或离线。

## 已完成（后端 API）
- `ChatCompletionRequest` 支持 `time_context`（内部字段为 `user_time_context`），包含 `local_time`、`timezone`、`utc_offset_minutes`。
- `AppConfig` 新增 `features.experimental_enable_chat_with_user_time_context` 作为实验开关。
- Agent 仅在开关开启时注入 `##User Time Context` 系统提示词，并包含“不应声称需要睡觉/离线”的约束。
- v1 / v2 chat 端点透传 `user_time_context` 到 Agent。
- 补充单元测试：开关开启时注入提示词内容。

## Android App 规划（最小必要）
- 聊天请求构造时采集设备本地时间、时区、UTC 偏移并写入 `time_context`。
- 仅在客户端实验开关开启时发送该字段，保持可快速回滚。

## 其他必要计划
- 在目标环境配置中打开 `app.features.experimental_enable_chat_with_user_time_context` 进行小范围试验。
- 使用现有用户反馈渠道（点赞/举报/运营反馈）观察效果，先验证反馈再扩展。

## 潜在点子

- 用户登录/注册时提供时区信息、由后端根据时间流逝推算时间；目前没有必要，但是似乎可以简化一些复杂度？
