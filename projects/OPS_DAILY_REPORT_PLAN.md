# OPS_DAILY_REPORT_PLAN.md
# CREATED_BY_AGENT: GPT-5.2

## 背景与目标
运营日报需要在运营平台的 dashboard 中展示“前一天所有用户的数据表现”。现有 https://app.inty.cc/evaluation 的“用户数据分析”Tab 已包含多数指标，本计划将其日维度化、定时产出并沉淀到日报。

## 目标范围
- **日报范围**：前一日（UTC 日历日）全量用户数据。
- **展示位置**：运营平台 dashboard 新增“运营日报”板块或页面。
- **对齐指标**：与“用户数据分析”Tab 的指标口径保持一致。

## 核心数据口径（对齐现有分析页）
1. **用户与聊天概览**
   - 用户数、发起聊天人数、包含用户消息的会话数、总发送消息数
   - 人均消息数、人均会话数、每会话平均轮数、开口率
2. **热门角色**
   - Top 20 角色：浏览数、真实发起聊天人数、开口率、总轮数、人均轮数、>=5/10轮占比
3. **轮数分布**
   - 按 Session 与按用户的轮数分布区间
4. **达到聊天限制**
   - 按认证类型汇总 GUEST/GOOGLE 达到限制人数
5. **增量指标（若现有已有）**
   - 生图统计、语音通话统计

## 产出方案（建议）
### 1) 定时生成
- **触发方式**：每日定时任务（UTC），统计前一日数据。
- **失败重试**：当日可支持补算与人工触发重算（避免漏报）。

### 2) 数据存储
- **落地形式**：日报表（按日期唯一）或对象存储（JSON）。
- **字段建议**：`report_date`、`data(JSON)`、`generated_at`。
- **约束**：同一日期可覆写（用于补算）。

### 3) API 提供
- **列表接口**：按日期范围获取日报列表。
- **详情接口**：按日期获取日报详情。
- **权限**：仅超级用户可访问。

### 4) 前端展示
复用现有“用户数据分析”的图表与表格组件，做以下差异：
- 报表日期选择（默认前一天）
- 读取日报 API（而非实时查询）
- 提示口径：UTC 前一日

## 运维与可观测性
- **监控**：日报生成耗时、失败数、数据为空告警。
- **日志**：记录 report_date、输入时间范围、生成结果摘要。
- **补算**：提供“重算某日”操作或运维脚本。

## 里程碑
1. **需求对齐**：确认日报指标清单与口径（对齐用户数据分析 Tab）。
2. **数据产出**：实现日报生成与落地。
3. **接口与权限**：提供日报 API。
4. **前端落地**：dashboard 展示日报。
5. **回归验证**：与现有分析页数据抽样对比。

## 风险与依赖
- **依赖**：现有数据分析服务、订阅用量表与 chat_history 口径一致。
- **风险**：前一日数据在统计窗口内延迟入库导致偏差。
- **缓解**：支持次日补算或 T+1 固定窗口延后触发。

## 验收标准
- 日报稳定每日产出且可按日期回看。
- 指标与“用户数据分析”页面在同一口径下抽样一致。
- dashboard 侧可视化完整、默认展示前一日。
