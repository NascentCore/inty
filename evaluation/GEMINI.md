# Gemini CLI Instructions

Unless explicitly instructed, follow the instructions below

## General

- Be concise
- Always run `npm run lint:format` before committing changes
- Always prefer use newer version of library/tools
- When there are multiple options, implement the best one, do not try to add multiple options
  for example, if there are 3 ways of launching the app by `npm run` `docker` `docker compose`
  just use `npm run`
- Assume development mode, which means keep track of changes closely

## High-level documentation

- All documentation is in markdown format
- New markdown file name must be with all upper-case letters and '_', with '.md' suffix
  Do not rename existing markdown file
- When generating new markdown file, always prepend 'GEMINI_' prefix to distinguish between tools
- When writing comments, always prepend comment text with 'GEMINI: ' to inddicate they are generated by gemini cli
- Based on description of the following markdown files to decide where to read and write documentation
  - README.md: Instructions for users of the tool implemented by everything under this folder
  - DEV.md: Instructions for developers & maintainers working on everything under this folder
