# Pydantic models for API endpoints

- Ops platform analytics schemas live under `app/schemas/analytics/` (e.g. user_analytics).
- **`/api/v1/chat/ws` JSON frames** (control/ack/ping, `ChatWebSocketRequest`, queued business envelope): [`app/schemas/chat_websocket.py`](/app/schemas/chat_websocket.py). Shared HTTP+WS chat body (`ChatCompletionRequest`, `UserTimeContext`, …): [`app/schemas/chat.py`](/app/schemas/chat.py).
- Must keep consistent between data types here and Kotlin DTOs under [`android_app/core/data/src/main/kotlin/ai/sxwl/android/data/api/model`](/android_app/core/data/src/main/kotlin/ai/sxwl/android/data/api/model) (e.g. `SendMsgReq.messageType` matches `ChatCompletionRequest.message_type`) and iMate [`ChatApiModels.kt`](/imate_android_app/app/src/main/java/com/inty/imate/chat/data/bean/ChatApiModels.kt). Companion WebSocket ``meta_data`` for user rows, assistant rows, and ``tool_bg`` frames is defined in [`app/schemas/chat_websocket.py`](/app/schemas/chat_websocket.py) as :class:`~app.schemas.chat_websocket.ChatWsCompanionWireMetaData` (``extra="allow"`` for forward compatibility). Chat assistant `meta_data.tool_background_started` (snake_case JSON) maps to Kotlin `MsgMetaData.toolBackgroundStarted` on companion WebSocket foreground frames when a background tool loop is running. Optional **`meta_data.inner_tick_activity`** (`proactive_chat` | `maintenance`) tags companion inner-tick rounds for ops/REPL; product clients may ignore unknown keys. Companion voice-as-message: assistant `meta_data.reply_modality` (`text` | `voice_message`), optional `voice_message_script`, `is_voice` when primary delivery is a voice note; `meta_data.audioDuration` (camelCase) may be set when `audio_url` is persisted for TTS output.
- **iMate** [`ChatApiModels.kt`](/imate_android_app/app/src/main/java/com/inty/imate/chat/data/bean/ChatApiModels.kt): **product** implicit greeting uses `ChatUserSignedOnWsMessage` with **`implicit_greeting`** + **`message_id`** (per agent, per WebSocket connection); wire may still use **`IMPLICIT_USER_SIGNED_ON`** chat frames where schema allows (same companion semantics as internal synthetic). Assistant `meta_data.messageType` may echo **`IMPLICIT_USER_SIGNED_ON`** for that turn. IntelliMate contract may differ. Product copy: [`/app/core/agentic_kernel/companion/implicit_signal_messages.py`](/app/core/agentic_kernel/companion/implicit_signal_messages.py). Control frames (Pydantic in `app/schemas/chat_websocket.py`): `ChatWsUserSignedOnFrame` / `ChatWsUserSignedOutFrame` / `ChatWsWsConnDroppedFrame` (`type` `user_signed_on` / `user_signed_out` / `ws_conn_dropped`); wire-only acks `user_signed_on_ack` / `user_signed_out_ack` / `ws_conn_dropped_ack` (Kotlin `shouldDeferChatResponseParsing`). `ws_conn_dropped` is used by the terminal REPL after transport reconnect to log context to companion `CHAT_LOGS.md`; mobile clients may adopt the same contract later.
- **`ws_conn_id` (handshake query + server logs, not JSON body):** Clients **should** send an RFC4122 UUID as query **`ws_conn_id`** on **`GET /api/v1/chat/ws`** and **`/ws/verify`** (alongside existing `agent_id`, `token`, `assume_user_id` as applicable). The server parses it after `accept()`; if missing or invalid it **generates** a new UUID and logs **`chat_ws ws_conn_id_query_invalid`**. The normalized id prefixes **loguru** lines (`chat_ws session_open` / `session_end`, control-frame handlers, `companion_ws_inner_tick_poll`, proactive heartbeat, maintenance inner-tick). It is **not** a Pydantic field and **not** echoed in assistant JSON. It does **not** replace turn correlation: use **`user_msg_uuid`**, **`inty_trace_id`**, and LangSmith ids for that. Companion runs **in-process** in the same API worker as the WebSocket handler (per worker process scope).
- Also keep consistent with [SqlAlchemy table models](/app/models/)
- Do not use `model_config` as field name in Pydantic Model objects,
  which conflicts with <https://docs.pydantic.dev/2.0/usage/model_config/>
