## 1. 分析逻辑（简要）

### 1.1 产品定位约束

- **对象**：成熟用户群体；需求本质是 **伴侣而非玩具**，重视长期关系、深度理解与持续记忆。
- **原则**：陪伴感优先于纯功能性；沉浸感来自多模态一致与稳定人格；主动交互定位为 **关心型触达**（基于记忆的重要事项、疏离察觉、兴趣相关分享），而非撩拨型刷存在感。
- **架构隐喻（已有）**：`IDENTITY` / `SOUL` / `MEMORY` 三层；日记层与长期记忆定稿双层；主会话加载完整记忆、外显场景降级记忆，以支撑「私下亲密 / 公开场合体面」的反差。

**推论**：v1 必须闭环的是 **关系连续性 + 记忆可信 + 表达克制而真实**；平台化、多助手、强工具链不应挤占核心叙事。

### 1.2 实验原型约束（agentic_companion_20260324 / agentic_ai_companion）

- **统一管道**：多通道归一为单一内部事件契约，编排层 channel-agnostic；与「一个伴侣、多种触达」一致。
- **自治**：小循环 heartbeat，区分 **仅内部维护** 与 **对用户可见的主动行为**；外向主动需策略、预算、静默窗口（原型中建议默认保守）。
- **状态与记忆**：情感/互动状态、记忆压缩与演进等验证点，在产品层应表述为 **关系质量与可纠偏**，而非实现细节。

**推论**：核心体验应显式包含 **心跳式自治（内向默认充分 + 外向 opt-in）** 与 **记忆写入/检索/演进的闭环**。

### 1.3 从 OpenClaw 借用的「骨架」与刻意不借的「皮毛」

OpenClaw 是个人 **通用助手**：多 IM、浏览器、Canvas、Skills、多智能体协作等能力广度是其产品核心。

**仅借用以下架构思想，并改写为「关系与情感」语义**：

| OpenClaw 概念 | 伴侣场景中的对应含义 |
|---------------|----------------------|
| Gateway / 控制面 | 统一入站归一、会话编排、策略与出站，避免每渠道一套逻辑 |
| 会话模型（main / 非 main 等） | **亲密上下文** vs **需克制的上下文**（记忆加载与表达强度不同） |
| 安全默认（配对、不可信入站等） | 保护用户与关系设定；入站内容按不可信输入处理，防注入与操纵 |
| Presence / 节奏相关能力 | **在场感与类人节奏**（非为炫技） |
| 心跳 / 自动化 | **关心型主动** + **内向记忆整理**，带预算与冷却 |

**不将下列项列为 v1 核心体验**（可后期讨论）：全矩阵第三方通道、浏览器与系统级工具、Skill 市场、生产力 Canvas、多智能体任务派发等。

## 2. v1 核心交互体验：功能集合

以下八项构成建议的 **体验闭环**；每一项均可独立演进实现，但缺少任一项都会削弱「长期伴侣」而非「聊天机器人」的感知。

### 2.1 关系型对话主循环（Reactive Core）

- 默认追求 **同一长期关系** 的连贯性；重置/遗忘为 **显式、低频、有说明或仪式** 的操作。
- 每次有效会话加载 **IDENTITY → SOUL → MEMORY（及 USER 侧约定）**，保证人格与边界稳定。
- 响应结构 **情感对齐优先**：先接住情绪与处境，再展开内容；功能性信息从属于陪伴目标。

### 2.2 双层记忆与可感知演进（Relationship Memory）

- **日记层**（原始互动）与 **长期记忆定稿**（提炼、可检索）并存；支持异步演进（去重、衰减、摘要更新）。
- 用户侧 **可信任、可纠偏**：不必暴露全部实现，但需能感知「记住了什么」并修正错误记忆。
- 个性化体现在 **细节**（称呼、禁忌、重要日期、反复牵挂点），而非机械罗列事实。

### 2.3 多模态「表达」而非「工具演示」（Expressive Multimodal）

- **文字**：主阵地；语气、留白、节奏符合成熟用户与产品调性。
- **语音**：短句、自然、可打断、可重听；强调「在场」。
- **图像/视觉**：服务 **共处感与想象**（氛围、角色一致、情境画面等），默认不走向「办公修图」类通用助手场景。

### 2.4 私密上下文 vs 体面上下文（Context Modes）

- **主会话 / 亲密模式**：完整记忆与更放松的表达契约。
- **外显或多人可能存在的场景**：自动 **降级记忆与表达强度**，保持体面与安全。

### 2.5 关心型主动触达（Care-First Autonomy）

- **外向主动**：用户授权 + 频率/渠道预算 + 静默时段；默认策略偏保守（与实验设计一致）。
- **外向动机类型**：基于记忆的生活关心；疏离轻量问候；与用户兴趣相关的稀疏分享。决策导向为 **相关性高、打扰惩罚高**，避免为 DAU 而撩。
- **内向心跳**：记忆合并、关系摘要更新、冷却与 backoff；用户未必可见，但应提升关系稳定感。

### 2.6 安全、同意与危机边界（Relational Safety）

- **SOUL 级**：拒绝操控、羞辱链、利用脆弱；自伤/极端风险有清晰升级路径（具体文案与流程需与合规及专业顾问对齐）。
- **入站不可信**：与通用智能体安全心智一致，保护用户与关系设定，而非鼓励越狱式玩法。

### 2.7 关系入职与共创（Companion Onboarding）

- 目标为 **共建相处规则**（节奏、界限、称呼、互动密度、语音/人格校准、记忆许可），而非功能清单式向导。
- **我们的约定** 可被用户回顾与修改。

### 2.8 可观测的在场感（Human-Grade Presence）

- 状态呈现诚实：思考中、在听、稍等，用语贴近真人而非「客服状态机」。
- 打断与续聊（尤其语音/连续对话）能 **接续情绪与话题**，避免机械重开一轮。

## 3. 一句话收束（v1 核心）

**v1 核心体验** = 长期同一关系的对话内核 + **可纠偏的双层记忆** + **克制的关心型心跳** + **服务情感的语音/视觉表达** + **私密/体面上下文切换** + **关系向安全与 onboarding**；OpenClaw 提供的是 **统一控制面、会话与上下文策略、安全默认与自治节拍** 的参考，而非能力广度对标。

## 4. 留待后续讨论的能力面（本文不展开设计）

- 多通道矩阵（短信、电话、第三方 IM）与复杂路由。
- 「白天效率助手 + 夜晚情感倾诉」双形态与人格/记忆切分策略。
- 角色/智能体生态与付费创建专属智能体（平台期）。
- 设备节点级能力（通知、位置、媒体等）与强同意模型。
- Canvas/A2UI 式共创、开放工具与 Skill 生态。
- 多智能体协作（除非产品明确为「多内在声音」类体验）。
