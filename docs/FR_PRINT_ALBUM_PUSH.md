# FR_PRINT_ALBUM_PUSH：相册打印及推送（参考 Google Photos 功能形态）

## 1. 背景与机会
- 用户拍照量大但高质量回忆沉淀不足，实体相册具备情感价值与礼物属性。
- 参考 Google Photos 常见功能形态（人物聚类、回忆/相册建议、打印入口），提出“智能发现 + AI 排版 + 实体打印 + 推送转化”的闭环。
- 本 PRD 为内部概念方案，若需严格对标 Google Photos，请补充正式产品调研。

## 2. 目标与非目标
### 目标
- 自动发现“用户与多人合照”的优质照片，形成可打印相册。
- 使用 AI 智能体完成排版，降低用户操作成本。
- 通过推送与应用内卡片提升打印转化。

### 非目标
- 不做通用相册编辑器替代。
- 不提供公开相册分享为核心路径（可作为后续增量）。

## 3. 目标用户
- 高拍照频次用户（旅行、家庭、社交聚会）。
- 有礼品或纪念场景需求的用户。
- 对自动化整理与推荐有偏好的用户。

## 4. 需求概述
- 系统自动识别用户与多人同框的高质量合照，形成候选照片集。
- 以事件/人物聚类生成相册建议，AI 智能体完成排版并产出可编辑预览。
- 用户一键确认并支付，后台对接打印履约，推送物流与收货提醒。

## 5. 用户故事
1. 作为用户，我希望自动收到“聚会合照”相册建议，几秒内完成下单。
2. 作为用户，我希望在下单前能快速预览并替换少量照片。
3. 作为运营，我希望通过推送提升打印转化，并可控打扰频次。

## 6. 功能需求
### MUST
- 用户身份确认：基于头像/自拍视频/已标记人脸建立用户身份向量。
- 合照发现：用户同框且其他人脸数量 ≥ 2，按时间与地点聚类成事件。
- 质量筛选：清晰度、曝光、闭眼、遮挡、人脸面积、重复度去重。
- 相册建议：自动生成封面与标题，给出可打印页数与价格估算。
- AI 排版：智能体输出页级排版方案，支持用户替换/调整照片。
- 打印履约：支持规格、地址、支付、订单状态与物流跟踪。
- 推送触达：应用内卡片 + 推送通知，支持频次控制与静默时段。

### SHOULD
- 亲密度排序：基于共同出镜频次、通讯录/互动信号优化人物排序。
- 主题化模板：旅行/生日/毕业/家庭等主题皮肤与配色。
- 多版本建议：同一事件提供“精简版/全量版”可选。

### COULD
- 礼品包装与贺卡选项。
- 会员折扣与长期订阅打印计划。
- 多人共建相册（后续阶段）。

## 7. 体验流程（用户视角）
1. 后台自动生成相册建议（“与你和好友的聚会合照”）。
2. 应用首页出现建议卡片，推送提醒。
3. 进入预览：查看封面、页数、价格与预计到货时间。
4. 一键下单或少量替换（最多 5 张）。
5. 完成支付，进入履约与物流跟踪。
6. 收货后评价与再次购买引导。

## 8. 关键规则：合照与“众美人”定义
### 合照判定（基础规则）
- 用户人脸在画面中，且其他人脸数量 ≥ 2。
- 画面质量达标：清晰、曝光合格、人脸无遮挡。
- 同一事件内重复照片去重（相似度阈值）。

### “众美人”解释与安全边界
- 以“多位重要人物 + 高质量人像”为目标，不做主观外貌评分。
- 如需个性化“美感”偏好，应由用户显式授权，且使用可解释信号
  （收藏/点赞/分享/亲密度/出镜频次），避免引入偏见风险。

## 9. AI 排版智能体（Layout Agent）
### 输入
- 候选照片（带人脸框、质量分、事件/人物标签）
- 相册规格（尺寸、页数、纸张）
- 主题模板（配色/边距/字体）

### 输出
- 结构化排版方案（JSON）：每页模板、照片分配、裁切区域、标题。

### 排版策略
- 优先保留人脸完整与主体比例。
- 事件叙事：按时间线/场景转场。
- 版面平衡：大图/拼图混排，避免同页重复人物。

### 质量检查
- 规则校验：人脸不可被裁掉、单页不重复。
- 评分回路：人脸比例、视觉平衡、留白合理性。

## 10. 数据与模型（概念）
- photo_asset：照片元数据、质量分、相似度簇 id
- person_cluster：人脸向量与聚类关系
- user_identity：用户身份向量与置信度
- album_suggestion：候选相册、来源事件、覆盖照片
- album_layout：页级排版 JSON 与渲染资源
- print_order：规格、价格、地址、状态、履约信息

## 11. 推荐实现方法（架构与流程）
### 端侧（优先保护隐私）
- 端侧完成初步人脸检测、质量评分与去重。
- 仅上传必要向量/元数据到后端（可选端侧全量处理模式）。

### 后端服务
- PeopleGraphService：人脸聚类与用户身份匹配。
- EventClusterService：按时间/地点聚类事件。
- AlbumSuggestionService：生成建议相册与候选照片集。
- LayoutAgentService：调用智能体生成排版 JSON。
- PrintOrderService：对接支付与履约供应商。

### 打印履约
- 对接第三方打印厂商 API（下单、状态回传、物流）。
- 失败回退：异常订单自动退款或重新下单。

## 12. 推送与触达策略
- 触发条件：事件结束 24-72 小时、月度回忆、节日前夕。
- 频次控制：每月最多 1-2 次强推；可在设置中关闭。
- 渠道组合：应用内卡片 + 推送通知 + 邮件（可选）。

## 13. 指标与验收
- 建议覆盖率：有建议的活跃用户占比
- 点击率：建议卡片 CTR
- 转化率：预览到下单转化
- 履约质量：退款率、物流超时率
- 复购率：30/90 天再次下单

## 14. 风险与合规
- 隐私：默认不上传原图；提供一键删除与数据导出。
- 误识别：提供人工替换与“此照片不推荐”反馈。
- 偏见：避免外貌打分，采用可解释、可控的偏好信号。
- 成本：大规模计算与履约成本需设置阈值与预算上限。

## 15. MVP 范围
- 仅支持“用户 + ≥2 人”合照事件。
- 固定 2-3 套模板与单一相册规格。
- 基础推送与应用内卡片，不做邮件。
- 仅支持单一打印供应商。

## 16. 里程碑（建议）
- M1：端侧检测 + 事件聚类 + 相册建议预览
- M2：AI 排版 + 订单支付 + 履约回传
- M3：推送策略 + 数据指标 + 体验优化
