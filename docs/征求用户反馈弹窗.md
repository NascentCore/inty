# 征求用户反馈弹窗

本文档说明 IntelliMate Android App 中“征求用户反馈”弹窗（`FeedbackRequestDialog`）的触发方式、阈值配置与展示入口，便于产品、运营与研发统一认知。

## 触发方式总览

当前有两种触发路径：

1. **本地触发（聊天会话内）**：在聊天页由 `ChatViewModel` 判断后触发。
2. **服务端推送触发（FCM）**：收到 `type=feedback_request` 的消息后，由 `MainActivity` 在前台触发。

---

## 1. 本地触发（聊天会话内）

### 触发位置

- 文件：`android_app/app/src/main/kotlin/com/ai/intellimate/chat/viewmodel/ChatViewModel.kt`
- 逻辑：在 `HttpResult.Success` 分支中，AI 成功回复后执行反馈弹窗判断。

### 触发条件（同时满足）

- 会话消息数达到阈值：`sessionMessageCount >= SESSION_MESSAGES_COUNT_THRESHOLD`
- 距上次弹窗时间达到最小间隔：`timeSinceLastShow >= MIN_SHOW_INTERVAL_MS`

对应配置常量：

```kotlin
object FeedbackDialog {
    const val SESSION_MESSAGES_COUNT_THRESHOLD = 30
    const val MIN_SHOW_INTERVAL_MS = 3 * 24 * 60 * 60 * 1000L // 3天
}
```

来源文件：`android_app/app/src/main/kotlin/com/ai/intellimate/ui/UiConfigs.kt`

### 具体执行流程

1. AI 消息成功返回后，`sessionMessageCount++`。
2. 读取 `IntySetting.getFeedbackDialogLastShowTime()`。
3. 与当前时间比较最小展示间隔（3 天）。
4. 若两个条件均满足：
   - 写入新的展示时间：`IntySetting.setFeedbackDialogLastShowTime(currentTime)`；
   - 置位 `chatViewModel.showFeedbackRequestDialog = true`，在聊天页弹出 `FeedbackRequestDialog`。

### 会话计数重置时机

- `MainActivity.onPause()` 会调用 `chatViewModel.resetSessionMessageCount()`。
- 因此这里的“会话消息数”可理解为：**App 从前台活跃到进入后台这段期间累计的消息数**。

---

## 2. 服务端推送触发（FCM）

### 触发标识

- FCM data 中 `type` 字段值为：`feedback_request`
- 常量定义：`FCMConstants.TYPE_FEEDBACK_REQUEST = "feedback_request"`

### 消息分发链路

1. `FCMService.onMessageReceived()` 收到消息。
2. `FCMessageHandlerImpl.handleMessage()` 发布事件：
   - `PushNotificationEvent.MessageReceived(messageId, type, title, body, data)`
3. `MainActivity` 订阅 `PushNotificationEvent.MessageReceived`，进入 `handleFeedbackRequestMessage(event)`。

`PushNotificationEvent.MessageReceived` 本身包含 `type` 字段（可用于业务分流）。

### 前后台显示策略

`MainActivity.handleFeedbackRequestMessage` 的逻辑：

- 若 `event.type != TYPE_FEEDBACK_REQUEST`：直接返回；
- 若类型匹配且 **App 在前台**：调用 `mainViewModel.showFeedbackRequestDialog()` 弹窗；
- 若 **App 不在前台**：仅记录日志，不弹窗。

### 通知栏行为

- 在客户端处理逻辑中，`feedback_request` 类型消息不会走常规通知展示路径（`FCMService` 与 `PushNotificationManager` 均有跳过通知的处理分支），预期由应用内弹窗承接。

---

## 弹窗展示入口（UI）

### 聊天页入口（本地触发）

- `ChatScreen` 监听 `chatViewModel.showFeedbackRequestDialog`；
- 为 `true` 时展示 `FeedbackRequestDialog`。

### 首页入口（FCM 触发）

- `HomeScreen` 的 `FeedbackRequestDialogLogic` 监听 `mainViewModel.showFeedbackRequestDialog`；
- 为 `true` 时展示同一个 `FeedbackRequestDialog`。

---

## 行为结论

- **本地触发**：受“会话消息数阈值 + 3 天最小间隔”双重限制，主要在聊天场景弹出。
- **FCM 触发**：由服务端 `feedback_request` 消息驱动，仅在 App 前台时由 `MainActivity/HomeScreen` 弹出。
- 两条路径最终都通过 ViewModel 的布尔状态置位来显示相同的反馈弹窗组件。
