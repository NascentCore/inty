# Dedicated repo documentation

- Use human redable format, and human understandable languages
- Do not use double-tick `` to quote
- Use ASCII & English (not Mandarin) for diagrams
- Be absolutely clear about the readers of your doc

## Design Doc

- Judge, not discuss
- Things must be included in a design doc:
  - Problem definition
  - Objectives
  - Bird's eye view of design
  - Key class, function doc string, and their interaction flows
