# 底部导航右滑返回测试步骤

CREATED_BY_AGENT

## 测试环境准备
- 构建 `local` 或 `debug` 变体（需打开系统手势返回）
- 登录有效账号，确保可访问 Chat/Explore/Messages/Profile 页面

## 用例 1：基本返回链路
1. 依次点击 `Chat → Explore → Messages → Profile`，确认每次切换后页面成功渲染。
2. 在 Profile 页面，从屏幕右缘向左滑动触发系统返回手势。
3. 观察页面切换到上一访问的 `Messages` Tab。
4. 重复右缘返回手势两次，确认依次回到 `Explore`、`Chat`。
5. 重复步骤 1-4，但改为从屏幕左缘向右滑动，确认效果一致。

**预期结果**：
- 每次边缘返回都会回到最近访问的 Tab。
- 页面内容与底部导航的选中状态同步更新。

## 用例 2：无历史时的退出提示
1. 将历史清空（例如重新启动 App，或在 Chat Tab 长按返回键直至退出提示出现）。
2. 停留在默认 `Chat` Tab。
3. 从任意边缘触发返回手势。

**预期结果**：
- 无 Tab 可回退时，显示原有的“再次返回退出”提示，第二次返回可退出应用。

## 用例 3：设置页优先级
1. 从任意 Tab 打开 `Settings`。
2. 在 Settings 页面触发边缘返回手势。

**预期结果**：
- 应优先关闭 Settings，回到先前 Tab；不会直接退出或跳转到历史 Tab。

## 用例 4：Create Tab 场景
1. 在 `Chat` Tab 点击中间的 `Create` 按钮，待创建完成后自动跳转到 `Profile`。
2. 在 `Profile` 页面触发边缘返回手势。

**预期结果**：
- 回退到 `Chat` Tab，证明程序化切换同样被记录在历史栈中。
