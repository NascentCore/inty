# Backend：可部署的 Inty 与 Ops 服务

**一句话**：仓库里有两套 **可独立部署的 Python 服务**——面向 App 的 **Inty 主后端**，以及带评测前端与运营 API 的 **Ops**；它们共享大量领域代码，但 **入口进程、默认端口与挂载的路由子集不同**。

## 双应用心智（比表格更直观）

- **Inty**：用户手机客户端默认连这里；挂载「产品化」的 `/api/v1` 路由树（聊天、订阅、角色等）。
- **Ops**：内部与评测使用；在 **同一套 `/api/v1` 前缀** 下额外挂载 **评测、节日记忆、与 Android 共用的共享端点** 等运营向能力，并通常承载评测 Web 静态入口。
- **记忆点**：健康检查、根路径行为在两套进程上 **可能不一致**；排查时先确认你连的是哪一个端口。

## 本地怎么跑（意图级）

- **数据库**：需要带向量能力的 Postgres（常见做法是用仓库提供的 compose 服务名拉起）。
- **主后端 + 推送 worker**：各用对应目录下的启动脚本；本地 HTTPS 或 HTTP 端口以脚本与配置为准。
- **Ops**：单独脚本启动，**默认另一端口**；首次本地评测前阅读 `backend/README.md` 获取当前推荐流程。

## Agent 子系统（传统「角色卡」路径）

- **Agent / AgentManager**：把「模型配置、提示词分层、会话历史、客户端复用」绑成可服务的实例池；强调 **缓存 + 闲置回收 + 配置热更新**。
- **配置优先级**：实例级 LLM 配置优先，缺省字段回落全局默认，避免半空配置上线。
- **提示词**：系统 / 模式 / 输出格式等多层叠加，并与 premium 等聊天设置联动。
- **历史**：会话历史来自数据库-backed 历史表，可按策略裁剪控制上下文长度。
- **资源与多媒体**：头像背景等往往伴随 **URL 形态归一化**（写库与回读可能形态不同）与 **尺寸元数据** 补齐。
- **语音**：以第三方 TTS 为主路径，生成开场白等资产并 **异步落盘/入库**；电话场景走 **PSTN 供应商 Webhook + 媒体流桥** 与实时模型衔接，**强依赖显式用户意图** 才外呼。
- **风控**：图像等生成路径在拒绝时应尽量给出 **可被前端展示的原因**。

## 与评测前端的耦合

- **评分模型列表** 等在后端、评测前端与缓存层有多份 **逻辑拷贝**；换模型不是单点改动，需 **跨栈同步** 并更新测试基线。细节以 `evaluation/AGENTS.md` 与代码为准。

## 术语速览

- Agent、角色卡、系统/角色提示词、记忆、扩展字段（extensions）、开场白（opening）——在文档与代码中常交替出现，阅读时把 **「持久化实体」与「一次推理用的 prompt 视图」** 区分开即可。
