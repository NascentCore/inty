# `evaluation/`：运营向 Web 评测台

**一句话**：给 **产品经理与运营** 用的浏览器工具——管理角色、跑评测、看用户行为数据；默认读者 **不是** 专业后端工程师。

## 心智与工程习惯

- **错误处理哲学**：不堆叠复杂兜底；假设使用者 **遇错会重试**（与 To C App 不同）。
- **访问后端**：一律走 **统一封装的 API 层**，不在组件里手写裸 `fetch` 路径拼字符串。
- **质量门槛**：改动需保持 **类型正确、测试（如 vitest）与构建** 通过。
- **图片展示**：图表与头像等 **不应被裁切到不可辨认**；布局上保证完整可读。
- **Assume user（超级用户）**：头部下拉可选任意已登记用户，后续单聊/语音以 **该用户身份** 拉历史；HTTP 与 WebSocket 上分别有对应头/字段传递此意图——**仅超级用户可见此能力**。
