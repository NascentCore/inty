# GitHub issue consolidate（组合治理 backlog）

面向 **整库 issue 组合**，不是单条 `/triage` 状态机。单条 `needs-triage` → `ready-for-agent` 仍用 [`.agents/skills/triage`](../../../.agents/skills/triage/SKILL.md)。

## AI 免责声明

GitHub 上 **创建/关闭/合并/评论** 的正文开头：

```markdown
> *This was generated by AI during issue consolidation.*
```

## 前置

- 仓库 clone 内、`gh` 已登录且有 `issues` 权限。
- [LABELS.md](LABELS.md) · [EPICS.md](EPICS.md) · [REFERENCE.md](REFERENCE.md)
- 导出 backlog：`bash .cursor/skills/scripts/gh_issue_audit_json.sh`

## 三种 invocation

| 意图 | 模式 |
|------|------|
| 新复杂需求落 ticket | **create** |
| 清理/合并 backlog | **audit → act**（先报告，确认后执行） |
| 长期路线图 | **epic**（见 EPICS.md） |

## create

1. Gather 上下文；复杂则 `/grill-with-docs` 或 `/to-issues` 切 slice。
2. 按 [LABELS.md](LABELS.md) 选域、类型、`p*`、triage 状态（新 issue 默认 `needs-triage`）。
3. 多 slice 强依赖 → 先 `[Epic]` 母 issue，子 issue 互链 `## Parent`。
4. `gh issue create --title "..." --body-file /tmp/body.md --label "a,b,c"`；body 用 [REFERENCE.md#issue-body-template](REFERENCE.md#issue-body-template)。

## audit

1. 跑 audit 脚本；按 **域 label** 分桶。
2. 每条归 **一类**：

| 分类 | 信号 | 建议 |
|------|------|------|
| stale | ≥90d 无活动，非 ready-* | close / ping |
| needs-info-stale | 等 reporter ≥30d | close / 最后 ping |
| duplicate | 同域同症状 | close → canonical |
| overlap | 部分 AC 重叠 | 合并 AC，close 其余 |
| coupled | ≥3 条同架构决策 | 提议 Epic |
| orphan-epic | Epic 无子 issue | 补链或降级 |
| healthy | 有 owner / ready-for-agent | 不动 |

3. stale/duplicate：**spot-check 代码库**是否已修复。
4. 输出表格 `# | title | class | reason | action`；**等 maintainer 确认**。

## act（仅 approved 项）

- Close：`gh issue close N --comment "…"`，链 canonical `#M`。
- Consolidate：合并 AC 到 canonical；被合并条 comment + close。
- Epic：按 [EPICS.md](EPICS.md) 建母 issue + 更新 checklist。
- Re-label：`gh issue edit N --add-label … --remove-label …`
- **勿** 删 issue；勿 batch close 报告外条目。

## 与其他 skill

| Skill | 用途 |
|-------|------|
| `triage` | 单条分类、repro、agent brief |
| `to-issues` / `to-prd` | 从 plan 切 slice / 写 PRD |
| **本 skill** | backlog 卫生、合并、epic 结构 |
