# Create GitHub issues and add TODOs

## When to use what

- **TODOs**: minor changes; like renaming, move code, delete code, etc.
- **GitHub issues**: large and complex follow-ups; after creating the issues, reference them in TODOs at appropriate code places. GitHub issues serve as the complete background; TODOs in code let agents trace from code to GitHub issues.

## Do not

- Do not reference issues in AGENTS.md or skills' MD files.

## Instructions

When creating issues, apply labels to distinguish them from other related issues and increase structuredness.

## Output

- List the created TODOs and issues
