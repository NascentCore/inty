# 消息生图失败与兜底分析结论

基于 `reports/` 目录下生图分析脚本产出数据（CSV 与 HTML）的总结。数据来源：`subscription_usage` 表，`usage_type = 'image_generation'`。

---

## 一、整体情况

| 指标 | 数值 |
|------|------|
| 总请求数 | 1,109 |
| 成功 | 744 (67.1%) |
| 失败 | 365 (32.9%) |
| 新生成 | 367 |
| 兜底 | 377 |
| 兜底占成功比例 | **50.7%** |
| 兜底占请求比例 | **34.0%** |

结论：约一半的「成功」实际来自兜底匹配，真正新生成仅约三分之一；约三分之一请求最终使用了兜底图。

---

## 二、失败原因分布

| 失败类型 | 次数 | 占比 |
|----------|------|------|
| safety_filter | 200 | **54.8%** |
| typeerror | 161 | **44.1%** |
| clienterror | 4 | 1.1% |

- **安全过滤**：约一半失败为 Gemini 安全策略（IMAGE_SAFETY、PROHIBITED_CONTENT 等）。
- **TypeError**：约 44% 为 `'NoneType' object is not iterable`，属代码在解析 Gemini 返回时对 `None` 做迭代，需在 `app/services/image_generation_service.py` 中对 `response.candidates` / `content.parts` 等做空值防护。
- **ClientError**：4 次为 429 RESOURCE_EXHAUSTED（Vertex 配额/限流）。

---

## 三、失败原因明细（Top）

1. `'NoneType' object is not iterable` (typeerror) — 161 次，需修代码空值判断。
2. FinishReason.IMAGE_SAFETY (safety_filter) — 122 次。
3. BlockedReason.PROHIBITED_CONTENT (safety_filter) — 39 次。
4. No content in candidates (finish_reason: FinishReason.IMAGE_SAFETY) — 21 次。
5. Image generation request blocked by safety filter: BlockedReason.PROHIBITED_CONTENT — 18 次。
6. 429 RESOURCE_EXHAUSTED — 4 次。

- **失败率很高**（请求≥5）：Sofia (75%)、Lifeguard Brayden (72%)、Svetlana Bondarenko (91.3%)、Summer Diaz (83.3%)、Kehlani (75%)、Test (100%)、Magnolia (75%) 等。
- **0 失败**：Teacher Maria、Palmer、Gabriella、Tris、Eliana、Sister Olive、Aurora Moore 等，说明非全局故障，而是部分角色或返回路径更容易触发安全或 None 分支。

---

## 六、结论与建议

1. **优先修代码**：在 `image_generation_service.py` 中对 Gemini 返回的 `candidates`、`content`、`parts` 等可能为 `None` 处做防御性判断，消除 `'NoneType' object is not iterable`，可预期消除约 44% 的失败。
2. **安全过滤**：属策略与内容问题，可做提示词/输入清洗、高风险角色策略或安全阈值评估（需合规）。
3. **429**：仅 4 次，可观察；若增多需查 Vertex 配额与限流，必要时加重试或降并发。
4. **兜底**：修掉 TypeError 并缓解安全拦截后，真实成功率上升，兜底占比会自然下降；可继续用日报/本目录报表按日、按角色监控。
